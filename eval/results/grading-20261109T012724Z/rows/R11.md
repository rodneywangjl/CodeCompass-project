## Question

Where does the inheritance chain between parent and child configuration classes affect configuration resolution when loading from a class object?

## Reference answer

The inheritance chain affects configuration resolution in the `from_object` method of the `Config` class, located in `./src/flask/config.py` at lines 218-254.

When `from_object` is called with a class object (like the child configuration class in the test), it uses Python's `dir()` function to enumerate attributes:

```python
def from_object(self, obj: object | str) -> None:
    if isinstance(obj, str):
        obj = import_string(obj)
    for key in dir(obj):
        if key.isupper():
            self[key] = getattr(obj, key)
```

The `dir()` function traverses the Method Resolution Order (MRO), which includes attributes from the class and all its base classes. In the test case (`test_config_from_class` at lines 132-141 in `tests/test_config.py`), when `from_object(Test)` is called:

1. `dir(Test)` includes attributes from both `Test` and its parent `Base`
2. It finds `TEST_KEY` from the parent class `Base` (line 134)
3. It finds `SECRET_KEY` from the child class `Test` (line 137)
4. Both are uppercase, so both are added to the configuration dictionary

This is verified by the `common_object_test` function (lines 13-16), which asserts that both `app.secret_key == "config"` and `app.config["TEST_KEY"] == "foo"` are present, confirming that attributes from the parent class are successfully resolved and loaded through the inheritance chain.

The inheritance chain's effect occurs specifically at line 252 where `dir(obj)` is called, as this function automatically includes inherited attributes in its result, enabling the configuration loader to access parent class attributes without explicit traversal of the inheritance hierarchy.

    def from_object(self, obj: object | str) -> None:
        """Updates the values from the given object.  An object can be of one
        of the following two types:

        -   a string: in this case the object with that name will be imported
        -   an actual object reference: that object is used directly

        Objects are usually either modules or classes. :meth:`from_object`
        loads only the uppercase attributes of the module/class. A ``dict``
        object will not work with :meth:`from_object` because the keys of a
        ``dict`` are not attributes of the ``dict`` class.

        Example of module-based configuration::

            app.config.from_object('yourapplication.default_config')
            from yourapplication import default_config
            app.config.from_object(default_config)

        Nothing is done to the object before loading. If the object is a
        class and has ``@property`` attributes, it needs to be
        instantiated before being passed to this method.

        You should not use this function to load the actual configuration but
        rather configuration defaults.  The actual config should be loaded
        with :meth:`from_pyfile` and ideally from a location not within the
        package because the package might be installed system wide.

        See :ref:`config-dev-prod` for an example of class-based configuration
        using :meth:`from_object`.

        :param obj: an import name or object
        """
        if isinstance(obj, str):
            obj = import_string(obj)
        for key in dir(obj):
            if key.isupper():
                self[key] = getattr(obj, key)
